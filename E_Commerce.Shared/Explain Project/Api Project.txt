فكرة GraphQL API

GraphQL هو أسلوب لبناء الـ API بيخلي الـ Client (زي الويب أو الموبايل) هو اللي يحدد البيانات اللي محتاجها بالظبط، بدل ما السيرفر يفرض عليه شكل ثابت.

المشكلة في REST

في REST بيحصل حاجتين:

Over-fetching → تاخد بيانات زيادة مش محتاجها
Under-fetching → تحتاج تعمل أكتر من Request عشان تجيب كل البيانات
الحل في GraphQL

في GraphQL:

بتبعت Request واحد بس
بتحدد فيه: "أنا عايز إيه بالظبط"
السيرفر يرجع نفس البيانات دي فقط
مثال بسيط

بدل ما تعمل:

/users
/users/1/posts

في GraphQL:

Request واحد تجيب بيه:
اسم اليوزر
البوستات
المكونات الأساسية
Query

لجلب البيانات (زي GET)

Mutation

للإضافة أو التعديل أو الحذف

Schema

ده العقد اللي بيحدد:

أنواع البيانات
العلاقات
إيه اللي ينفع تطلبه
المميزات
مرونة عالية
Request واحدة بدل كذا واحدة
مناسب جدًا للـ Frontend
العيوب
أعقد شوية من REST
محتاج تنظيم كويس
